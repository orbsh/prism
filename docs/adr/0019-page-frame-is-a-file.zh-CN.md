# 0019 — 页面外框是一个文件，区域是一个地址

状态：已采纳（2026-11-09）

## 背景

在此之前，页面完全由回答 `ui:connect` 的那个 booth 画出。gravity 的回答是约一百行 Rust：导航条、分页器、auth 区、notice 区，加两个页面，一次性以 `create` 加若干 `append` 发出。

这让三件事成立，没有一件是本意：

1. **一项布局决定住在应用里。** 这个页面有哪些区域、导航条写什么、登录界面放哪，全都属于运维；而这些没有一样能在不重新构建 booth 的情况下改变。
2. **一个 booth 看不见另一个 booth 的区域。** 由一个应用拼出的页面，只能装得下这个应用的界面。第二个 island（比如授权页）无处可画，因为本该托住它的东西，由一台从没听说过它的机器画。
3. **每个应用都必须画一整页。** 「用 `create` 回答 `ui:connect`」这条规则，只在恰好存在一个应用时才说得通。

前端元框架的解法是打包：把几套技术栈塞进一个产物，把边界留给运行期约定。它从来没提供让 island 成立的那两样东西——一个区域可以被写入、而不必知道别的任何事的地址，以及一个「更新单元与隔离单元是同一件事」的模型。

## 决定

**外框是运维写的一个文件；区域是以 booth 命名的 slot。**

- `PRISM_SHELL` 指向一个 JSON 文件，内容是一个 accrete 文档。prism 在启动时读它（读不了、或里面是一串动作，都是启动错误，不是静默降级为「没有外框」），并在每条渲染连接上推一个 `create`，其 data 就是该文档——**先于** `ui:connect`，因为用 `set` 回答的 booth 需要一个已经存在的 slot。
- 区域在该文件里声明为 `{"bind": {"value": {"kind": "source", "source": "island:<booth 类型>"}}}`。slot 名就是地址：没有映射表、没有注册，没有任何会与文件不一致的东西。部署改了 booth 名，改的就是一个字符串。
- **前缀是平面的，不是 booth 的。** 被托管时，booth 用**空 slot** 指自己这块界面，内部名字照写裸名（`pages`、`notice`）；视图腿把该 booth 帧里每个 slot 改写成 `island:<页面给它的名字>/<slot>`，其中页面给的名字是事件名的第一段（`ui:gravity-model.layout` ⇒ `gravity-model`）——不是 aura 的 booth 类型，页面不认识引擎。已经写成 `island:…` 的 slot 原样通过：要写进别人的区域，得知道那个名字，而没有 booth 会被告诉它。
- 平面发出的每一条投递都在顶层带 `shell: true|false`：`true` 表示外框已由平面画出，此时一个 `create` 会替换根节点、把导航和同页其他 island 一起擦掉；`false` 表示照旧由 booth 画整页。
- **外框的动态面只有两个槽，由平面填。** `user` 放「谁在看」（设备别名，或短 id，未绑定账户时标 `(guest)`），`nav` 放「每个 island 一项」，标签取自外框自己的 `attrs.label`。两者都在每次连接时写入，且都在 `ui:connect` **之前**。两者都是 booth 永远拿不到的事实——身份在每次上行时由服务端解析（ADR-0018），而部署有哪些区域是外框自己的事。
- **切换用 fluxen 的 `pages`，本地驱动。** 外框声明 `regions: [{booth, label}]`（这条声明不渲染任何东西）；平面提供让它成立的两行数据——一个 `nav` 项和一行同 id 的 `pages` 行，行里装该区域的绑定——外框把 `select` 与 `pages` 节点接到同一个本地 `page` 值上。于是切页对已经访问过的岛不产生往返：第一次落到某个岛上的点击会上报它（`local` 绑定的 `report`，fluxen ADR 0028），因为这是只有平面才握得住的一条事实——它记住这个人站在哪里、只叫那一个 booth；首次访问之后，点击就留在本地。行由平面提供，是因为页面行只能来自 list 槽；静态子节点会成为把页面放上屏幕的第二种办法，而且是切不走的那一种。
- **应用自己的初始布局不能是文件。** 聊天界面回答一次连接时，先给布局、再按情况给这份布局该显示的内容——形状取决于数据（历史、在线状态、是不是第一次），所以两者是同一次初始化。文件在启动时就固定，对连接一无所知。分界就在这里：外框固定且共享，应用的界面按连接而生。
- 不设 `PRISM_SHELL` 是合法的，含义是旧安排。`crates/prism/assets/shell.json` 是参考外框。

## 考虑并否决

- **一个 shell booth。** 它画的是常量；而一个常量若要走 booth，就得付生命周期、接收声明和一种失败形态（booth 没注册，页面就没有外框）。文件只有一种失败形态，在启动时，摆在运维眼前。
- **在 prism 配置里发明外框 DSL。** KDL 对人更好读，但这里写的是视图，而线上已经有视图的形状。给同一棵树再发明一种拼法，买不到任何东西，却让需要同步的东西翻倍。
- **每个 island 都往同一个根 `create`。** 它们会互相覆盖，而那正是 slot 边界存在的理由。

## 后果

- 外框的主人是运维，不是 booth。改导航就是改文件、重启 prism，不牵涉任何 crate。
- island 就是一次普通的 `set`，写进平面推导出的名字。于是隔离单元与更新单元是同一个对象：渲染器重画的恰好是绑定该 slot 的节点；而隔离是**机制**而不是纪律——写 `pages` 的应用拿到的是 `island:<它的名字>/pages`，要够到别人的区域，得写出一个没人给过它的名字。
- 地址约定取代了配置，而启动日志会说明它找到了什么（`prism: page frame ← … (islands: …)`），所以一个本意要有导航的部署会说出口。
- gravity 的外框与屏幕仍然用代码构造那棵树，只有**地址**由标志决定。树本身仍归 gravity —— 这是对的：应用在自己的区域里画什么，是它自己的事。
