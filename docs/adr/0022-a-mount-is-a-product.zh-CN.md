# 0022 — 一道 mount 是「词表 × 已批准的 alias」的积

> **语言 / Languages:** [English](0022-a-mount-is-a-product.md) (primary) · [中文](0022-a-mount-is-a-product.zh-CN.md)

**Status:** Accepted（2026-11-20）

## Context（背景）

节点靠 mount 可调用：每个（alias × 操作语言）一个 `Remote` 类型，其 source 是固定 runner（gravity ADR-0001）。声明原先写在 `PRISM_MOUNTS` 里，每个 alias 一行，每次启动重放。

这个形状有两处坏掉，而且坏在相反的方向：

- **拨进来却没写进清单的机器，在场地里但不可调用。** 池子里有它，placement 能到达它，却没有一个类型可以寻址它。个人笔记本 —— 整个节点故事的主角 —— 非要写进部署清单才能用。
- **那一行背着两个属于不同所有者的信息。** 「这套安装能跑哪几门语言、各自用哪个部署件」是关于**安装**的事实：对每个节点都一样，随部署发货。「哪些机器是节点」是关于**注册表**的事实：一行批没批准。按 alias 一行，等于逼第二份名单用第一份的词汇再写一遍。

## Decision（裁决）

### 1. 词表是部署的，声明一次

`PRISM_LANGUAGES` 是一个 JSON 数组，元素为 `{language, carrier, runner, encoding?, requires?}` —— 这套安装能跑的操作语言，各自带 carrier、runner 部署件、帧编解码、所需隔离。缺席表示这套安装不跑任何节点代码，这是合法的，且启动时说出口。写错就是启动错误：那是部署事实，永不是默认值（ADR-0001 的规则不变）。

### 2. alias 名单是注册表的，而且它本来就在

每个（**已批准**行 × 词表条目）一道 mount，类型名为 `{alias}.{language}`。行上不新增任何字段：批准本身就是全部的事实。pending 行铸不出东西，revoked 行也铸不出东西 —— 与机器绑定同一条纪律（prism ADR-0020）。

alias 不得含 `.` —— 类型名是 `{alias}.{language}`，带点的 alias 会让两对不同的 (alias, language) 拼出同一个名字。拒绝发生在铸名字的地方（`POST /admin/nodes`），不在 mount 那里。

### 3. 每台节点服务整套词表；缺 runner 是环境的责任

不做逐节点的语言选择。一台机器拿到这套安装声明的全部语言；如果它缺某门语言需要的部署件，**调用**失败 —— 操作员或用户去修那台机器。另一种做法（铸 token 时逐台勾选）用一个每次都要付的步骤换一个更早的错误，并且那份手写清单会错在更安静的方向：语言在、runner 不在。

### 4. 注册发生在启动、批准后的下一次启动、以及一次拨号

- **启动**为每条已批准行派生并注册 mount：任何节点连上来之前，列表就是诚实的（`registered: true`、`node_connected: false`）。
- **一次拨号**为一个没见过的 alias 补表。`open` 姿态下这是唯一的名单 —— 边界就是网络，日志会说这些类型由一次拨号铸出。`required` 姿态下它覆盖「启动之后才被批准的行」，否则那台机器要等到下一次重启。
- 派生是幂等的：同一个 alias 再拨一次什么也不加。

### 5. `PRISM_MOUNTS` 退役

它的两半各自回到所有者手里（§1、§2）。留着它，就等于在注册表旁边再放一个答案，而这正是这份记录要消掉的漂移。

## 否决的方案

- **保留按 alias 的清单作为覆盖层**，与派生并存。又有两张名单，而且覆盖层会悄悄压过注册表 —— 部署可以为一个已被吊销的行声明 mount。
- **让拨入的节点自报语言**（取自 `Frame::Register` 的 carriers）。节点说"我能跑 python"是一个可猜的声称，与自荐标签（effector ADR-0005 §2b）同构；ADR-0001「没有数据路径能铸 mount」把它挡在外面。拨号声明的 carriers 仍有用途：场地拿它与词表比对并说出漂移，但不拒绝。
- **铸 token 时逐节点勾语言**（先前那个分叉）。按 §3 的裁决否决：它把环境失效挪到一个会说谎的勾选框上。
- **只在需要时派生**（第一次调用才铸类型）。调用方是先读「能调什么」再调；一个在调用时才自我充实的表，对任何列表都只能答"还没有"。
- **吊销时注销该行的 mount。** 类型留着、节点不在：调用答 "not connected"，列表报 `node_connected: false`。注销还得处理「作业刚刚按这个类型解析完声明集合」的情况。

## 后果

- **一台机器在它的 token 被批准的那一刻就可调用**，个人笔记本不再需要清单里的一行。
- **词表是整套安装的一份名单**，"这个场地能跑哪些语言"只有一个答案，加一门语言是一次部署改动。
- **调用期失败是设计的一部分**：缺 python 部署件的节点卖的是一个会失败的 python mount。列表无法知道（那得挨个问节点装了什么并相信它的回答）；失败会点出那道 mount，环境随后被修好。
- **类型名编码了两个谁都不解析的事实**：`{alias}.{language}` 对操作员可读，对其余一切是不透明的（`ctx.invoke` 收的是名字，不是路径）。
- **`open` 姿态下拨号会铸类型。** 那是该姿态的取舍，且在拨号处说明：能到达 gateway 的就是节点，于是拨上来的 alias 就可调用。`required` 姿态只从已批准行铸。

## 测试

- `crates/prism/tests/mount_listing.rs` —— `a_mount_is_the_product_of_the_vocabulary_and_an_approved_alias`：批准前无可调用；批准后每门语言一道 mount，`registered` 真而 `node_connected` 假；池子里有位之后在场翻真；`open` 姿态的派生在第二次拨号幂等；缺 `runner` 的词表是启动错误且已装的表不受影响。
