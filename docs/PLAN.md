# PLAN

Design lives in the wiki (stateless-agent-architecture.md); this file only sequences phases.

## Milestone A — WS gateway

- [x] Phase 0 — Workspace skeleton: `crates/{gateway,protocol,cli,config}`; protocol contract: turn submit / stream frames / cancel / session lifecycle, one message schema for all clients. LANDED 2026-09-25 as the ECHO plane (scope-reduced, README says so): `crates/{prism-protocol,prism}` (gateway+cli merged — no separate crates until they earn their boundaries); the one message schema IS the contract landed: `{ev, args}` both directions (§4), CBOR default + JSON debug, four-language echoes proving every carrier through a real socket. Turn submit / cancel / session lifecycle ride Phase 1's Gravity hosting.
- [ ] Phase 1 — WS gateway on Aura: resident component; client connections pin here (never on Gravity); auth + parse + turn submission as realm events; streaming back via event subscription (SSE-over-WS frames). Identity half LANDED 2026-09-25: device assignment + `?device=` restore (§2), signup/login as ordinary events on one socket with argon2id in PRISM's own okm instance (§4/§7), ONE connection set with a per-connection auth field driving `broadcast {to:"auth"}` (§3 — the two-set ruling superseded in ADR-0017 same-day; drift unrepresentable), sender envelope in delivery payload, Ctx untouched (§7 amendment; `echo_sender` proves it live); per-event auth ENFORCEMENT LANDED 2026-09-26 — the actor's persisted `interface_schema` `auth` block (presence of the handler name = the rule, value reserved) is read at dispatch BEFORE the call, anonymous senders get the standard error VALUE, `echo_priv` + `declared_auth_event_requires_a_bound_user` lock it (the check rides the upload-time introspection — one declaration surface, no second ACL table; fail-open on an absent/unresolvable block, matching §2's "commerce declares it, chat may never"). Also LANDED with it: prism Cargo.lock okm pin raised to aura's current rev (the StorageEngine trait-signature drift was breaking the path-dep build). Remaining: turn verbs + streaming on Gravity hosting, logout/revocation.
- [ ] Phase 1.5 — Scope note (no code): WS appears in exactly two stateful places — Prism↔clients (entry, this repo) and the control plane↔remote-Probe outbound long connections (hosted on Aura's connection plane, Phase 6.5 of aura; not this repo's gateway). Inside the realm there are no connections — Gravity↔Prism/Probe are realm events. No work in this repo; recorded to prevent protocol drift.
- [ ] Phase 2 — CLI wrapping WS: thin client — every CLI command maps to the same WS protocol; no second RPC surface. Local Krystallizer mode is Gravity's CLI, not Prism's.
- [ ] Phase 1.8 — Node identity, trust plane (aura ADR-0015 Update 2026-09-25 — attribution lands HERE, not in aura): the `identity` config field (no default; `required` | `open`), the ed25519 keypair handshake (`challenge{nonce}` → signed `register` → `registered`/`pending`/`conflict`/`unauthenticated`), the node registry (`{alias, public_key, status, created_at}` in prism's own okm instance), and the four curl approval endpoints under `/admin` (`POST /nodes`, `GET /nodes`, `POST /nodes/{alias}/approve`, `DELETE /nodes/{alias}`). Step ③ (fold records under the account) rides Phase 1's auth. Aura's landed residue (replacement discipline + startup disclosure) needs no change here — it is already true under whatever posture the gateway mounts.
- [x] Phase 1.9 — Static code export (aura ADR-0027) — LANDED 2026-09-26: `GET /code/{sha256}` on the SAME accept loop as the WS gateway — the request head is read raw (tungstenite 0.24's handshake callback cannot emit an early non-upgrade response, so the branch lives below the upgrade machinery), the export answers as a plain HTTP download with `Cache-Control: public, max-age=31536000, immutable`, every other path replays its head into the WS handshake through a prefix adapter (`code_export::Prefixed`). Same-process meta-plane read (`aura_realm::meta::get_blob`) — no proxy hop, the bytes were stored at registration by content addressing. No auth (the hash is the capability; §4's per-node ACL ruling stands). Strict address parsing: 64 hex chars = the lookup, malformed = 400, absent = 404 — never a truncated-key guess. Locked by `tests/code_export.rs` (the served blob is `echo_steel`'s real registered source; the body re-hashes to its own URL; the WS path survives the head replay on the same port).

Deferred gates:

- Multi-tenant auth (keys/accounts): single-user first; add auth layers only with the first external consumer.
- HTTP/SSE secondary endpoint: rejected by design (protocol unification); revisit only with a hard client constraint that cannot do WS.
