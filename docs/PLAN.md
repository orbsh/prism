- [~] Phase 1.8 — Node identity, trust plane (aura ADR-0015 Update 2026-09-25 — attribution lands HERE, not in aura). LANDED 2026-09-26 (step 1, prism's independent half): the node registry (`nodes.rs` — ns 52 in prism's own okm instance, the {alias, public_key, status, created_at} row of §4 on the registry pattern: proxy-id key + by_alias index + HighWater watermark), the verdict function implementing §3's `required` table (registered | pending | conflict, fresh claims auto-queue so the operator sees attempts, revoked keys revive to pending — never self-service), the trust posture as a constructed value with NO default (`Posture`, the binary refuses to boot without PRISM_IDENTITY and states the posture at startup — §7's disclosure), and the four curl-first approval endpoints (`admin.rs`: POST/GET /admin/nodes, POST /admin/nodes/{alias}/approve, DELETE /admin/nodes/{alias} — 400 malformed, 409 refuses the ambiguous decision, unknown admin route 404; they ride the same raw-head accept loop as /ws and /code; interim curl-first per §5 — account folding is step ③). STILL PENDING (step 2, coordinated cross-repo): the handshake EXECUTION — `challenge{nonce}`/signed `register` frames on `/probe/<alias>` (probe-protocol changes + the probe mount, which does not exist on prism yet; until it does, `required` has no node to gate — the verdict function is the seam that stays testable), `credential` deletion on both ends, and step ③ (records under the account, riding Phase 1's auth session). ORDER DECIDED (2026-09-26, user-approved): mount `/probe/<alias>` into prism FIRST (ADR-0017 §6 — the probe gateway currently lives in `aura/crates/engine/src/probes.rs`), so the handshake has a home on the connection plane before it is built; the probe-protocol frame changes ride with the mount (both ends move together, ADR-0015 Consequences). Aura's landed residue (replacement discipline + startup disclosure) needs no change here. DESIGN CONSTRAINTS RECORDED (2026-09-26, remote-booth discussion; argued and landed in aura ADR-0031, REVISED same day after user review — the revision supersedes the first draft these notes originally recorded): (1) two extension tiers, and trust follows OWNERSHIP, not capability — the probe tier is trusted to execute control-plane-written code (its heavier credential chain lives HERE: this plan's node registry); the booth tier splits by who vouches: an OWN-SERVICE remote booth is trusted because the realm owner deployed it (approval = the deployment decision itself, no ceremony, no account table), and a BROWSER (fluxen) is trusted through the user's session — this repo's device/user anchors + per-event auth block. (2) Connection direction is ownership's topology expression, not a knob: own services DIAL OUT (the realm connects to a remote WS endpoint; no credentials — the URL/allow-list is the identity; making the endpoint reachable is the deployer's problem, same as microservices), proxied sessions DIAL IN on this plane. The handshake must keep `Node` transport-only; the first draft's three key axes and the (account, booth_type) account-plane table are WITHDRAWN — the real key spaces are two: node keypair (transport) + device/user anchors (session). (3) Vocabulary is two mechanical rules, no grant ceremony: dial-out emits bare names (a mismatch is the owner's internal bug, ungoverned); dial-in emissions are prefix-stamped at the proxy boundary (`<account>/<session>.…`) before reaching the realm — fluxen's emits included — and the prefix is prism's envelope, stripped on egress for the session's OWN names only (foreign prefixes gated by the auth block or kept intact; provenance rides the sender envelope, not the name) — receives are gated by the existing per-event auth block. (4) Delivery to remote participants is LIVE: no cursor, no backlog, no replay — no connected endpoint = failed delivery as a value (delivery log / dead ring); durable queues stay realm-internal. (5) Own-service endpoints are WS servers on the realm's own frame vocabulary in CBOR (no webhook-POST shape — the obligation is identical and half-duplex POST is strictly worse); the dial-in browser mount speaks JSON. The Phase-1 streaming half is now load-bearing for fluxen-as-remote-booth (the first draft's "one mould with the probe" framing was withdrawn — same protocol vocabulary, differences confined to direction + vocabulary rule).
- [x] Phase 1.9 — Static code export (aura ADR-0027) — LANDED 2026-09-26: `GET /code/{sha256}` on the SAME accept loop as the WS gateway — the request head is read raw (tungstenite 0.24's handshake callback cannot emit an early non-upgrade response, so the branch lives below the upgrade machinery), the export answers as a plain HTTP download with `Cache-Control: public, max-age=31536000, immutable`, every other path replays its head into the WS handshake through a prefix adapter (`code_export::Prefixed`). Same-process meta-plane read (`aura_realm::meta::get_blob`) — no proxy hop, the bytes were stored at registration by content addressing. No auth (the hash is the capability; §4's per-node ACL ruling stands). Strict address parsing: 64 hex chars = the lookup, malformed = 400, absent = 404 — never a truncated-key guess. Locked by `tests/code_export.rs` (the served blob is `echo_steel`'s real registered source; the body re-hashes to its own URL; the WS path survives the head replay on the same port).

Deferred gates:

- Multi-tenant auth (keys/accounts): single-user first; add auth layers only with the first external consumer.
- HTTP/SSE secondary endpoint: rejected by design (protocol unification); revisit only with a hard client constraint that cannot do WS.
